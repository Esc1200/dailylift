YouTube API & OAuth Disclosure

Last updated: September 26, 2026

Introduction

This page discloses how the DailyLift publishing tool uses Google's YouTube Data API and OAuth authentication. It supplements the main Privacy Policy and exists because Google's OAuth consent screen requires a specific, accurate description of how Google user data is accessed and used.

The application

The application is a private, single-user command-line publishing tool operated by the DailyLift owner. It is not offered to third parties and has no other users. Its only function is to upload prepared video files to a YouTube channel and set each video's metadata.

Permissions requested

The application requests these OAuth scopes:

  • https://www.googleapis.com/auth/youtube.upload
  • https://www.googleapis.com/auth/youtube

These scopes allow the tool to upload videos and manage video settings on the authorised channel. They grant access to channel content only — not to personal account information.

The application does not request youtube.readonly, YouTube Analytics scopes, Google Analytics, AdSense, or any Gmail or Drive scope.

Exact API calls made

CallPurpose
videos.insertUpload a finished video file to the channel
videos.updateSet the video's visibility status and scheduled publish time
thumbnails.setSet the video's thumbnail image
channels.listRead the authorised channel's own name and public statistics, to confirm the correct channel was connected

No other YouTube Data API endpoints are called.

What the application explicitly does not do

  • It does not read, store, or process comments, replies, or comment threads.
  • It does not read, request, or store viewer analytics, watch time, demographics, or traffic sources.
  • It does not read, request, or store subscriber lists, email addresses, or any personal information about viewers.
  • It does not read the channel's playlists, drafts, inbox, or saved content.
  • It does not delete anything from YouTube. It cannot remove videos, comments, or any other content from the channel.
  • It does not transmit any channel or user data to us or to any third party. All requests are sent to Google (googleapis.com) and nowhere else.
  • It does not display advertising, serve ads, or share data with advertising networks.

How Google user data is used

Google user data is used for one purpose only: uploading videos to the authorised YouTube channel and setting their metadata so viewers can find and watch them. The data is not used for advertising, profiling, analytics, model training, or any other purpose, and it is not sold or shared.

Data storage and retention

Two items are stored, both locally on the single computer running the tool:

  • An OAuth access token, which proves the application is authorised. It is kept in a file outside the project directory, is never committed to a code repository, never written to logs, and never transmitted anywhere except Google's servers.
  • The authorised channel's name and public subscriber/video counts, read via channels.list and printed to the console so the operator can confirm the correct channel. Not transmitted, not shared.

The access token grants authority over a live YouTube channel. Anyone with access to that file can act on the channel until access is revoked. Tokens are not retained beyond their expiry and can be revoked at any time.

Revoking access

You can revoke this application's access at any time at myaccount.google.com/permissions. Revocation takes effect immediately and permanently disables the tool.

Human review of this disclosure

This document was written to match the actual behaviour of the application's source code. Every API endpoint listed above was verified against the code, and endpoints that are not called are listed under "does not do" so there is no ambiguity about the tool's data footprint.
